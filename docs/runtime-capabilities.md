# Runtime capabilities

AOS selects exactly one runtime per deployment. The browser always uses the normalized AOS proxy; provider URLs and credentials remain in its private configuration. Unsupported behavior stays visibly unavailable rather than being emulated by the browser.

Hermes, OpenClaw, and OpenCode are independently installed and operated
runtimes. Hermes is the primary and first-supported harness. The matrix keeps
that product order and places the newer OpenCode path last. The AOS UI tools
MCP server (`packages/tools-mcp`, registered as `aos-ui`) adds its chart, map,
and stats [MCP App](mcp-apps.md) views and `present_artifact` where stated; it
does not change the trust boundary. Any other MCP server that declares an App
view renders it the same way. Where the runtime keeps no App views, a temporary
proxy fallback reads them from the server's own URL and draws the card as soon
as the call starts; OpenClaw's native views draw once the result names them.
`content.mcpApps.maxBytes` advertises the 2 MiB view cap.

## Fixture

Use fixture mode to evaluate layout, localization, keyboard flow, rich output, and deterministic Activity behavior without a backend. Fixture state is not durable and deliberately excludes Agent creation.

## Hermes

Hermes owns profiles, Sessions, authentication, speech providers, tools, and persistence. AOS connects directly to the native HTTP/WebSocket API over the server adapter; the browser sees ACP v2. Native active-turn steering records a visible user correction and can fall back to Hermes's provider queue. Profile visibility is native. Each profile that registers the `aos-ui` MCP server gains its chart, map, and stats App views and `present_artifact`; an assistant `MEDIA:` line also publishes an Artifact. A profile marked as the creator stays out of the roster and offers **New Agent**; it creates profiles with the `hermes` CLI. Hermes keeps no MCP App views, so the proxy reads them itself from the profile's Streamable HTTP servers, `aos-ui` included, so the proxy must reach each server's registered URL, or the URL configured for it under `mcpApps.fallback`: servers without auth, or with headers configured there; a stdio or other authenticated server shows the textual details. See [Run Hermes](runtimes/hermes.md).

## OpenClaw

The OpenClaw adapter uses the authenticated, negotiated Gateway connection for provider-owned catalog, Session/history, run, interaction, attachment, model, and context operations. It does not expose the Gateway to browsers or infer native mutations that the pinned protocol does not prove. Session creation is available. The proxy enables the operator-registered `aos-ui` MCP server per Session, which requires `operator.admin`; its charts, maps, and stats are App views and need `mcp.apps.enabled: true`. A `present_artifact` receipt is read through `sessions.files.get` (workspace files only, 256 KiB, text or common images); OpenClaw's own media is read through `artifacts.download` and appears after a reload. MCP Apps are native: the proxy opens a view through `mcp.app.view` and relays its requests through `mcp.app.callTool` and `mcp.app.readResource` while the Gateway has `mcp.apps.enabled: true`. Rename, archive, delete, Todos, Activity, edit/regenerate, steering, and read state remain unavailable. Voice becomes available through the proxy `voice` configuration. See [Run OpenClaw](runtimes/openclaw.md).

## OpenCode

OpenCode owns Agent definitions, Sessions, execution, provider credentials, worktree, and persistence. The proxy attaches to its authenticated server using a fixed directory and server-side Basic authentication. AOS reads the catalog and session model choices, creates Sessions, and projects durable runs, questions, permissions, attachments, Stop, and reconnect. A `present_artifact` receipt is read through `GET /file/content`, confined to the project directory. The launcher registers the `aos-ui` MCP server, but OpenCode's v2 session engine does not expose MCP tools at the pinned 1.18.29, so the tools are not callable through AOS yet. MCP Apps use the proxy fallback for remote servers without headers or OAuth, or with headers configured under `mcpApps.fallback`; OpenCode stores only a tool's text output, so a view receives a text-only result. AOS intentionally does not invent catalog mutation, title/delete, Todos, Activity, context accounting, edit/regenerate, or steering semantics. Voice becomes available through the proxy `voice` configuration. See [Run OpenCode](runtimes/opencode.md).
